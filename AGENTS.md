# SkyFi Frontend — правила агента

Vue 3 + TypeScript SPA для бэка SkyFi (Laravel, API в `docs/api.md`).
Соседний проект бэка — `~/projects/SkyFi`, там работает бэк-агент.

## Документация: что чьё

Общая документация лежит в `docs/` обоих проектов и обязана совпадать
байт-в-байт. У каждого файла ровно один писатель:

- `docs/api.md`, `docs/contracts.md`, `docs/video.md` — **read-only
  зеркало бэка**. Не редактируй их вообще, даже если видишь
  расхождение с реальностью (проверил curl'ом — тем более не правь):
  сообщи пользователю, исправление вносится на бэке и доезжает
  сюда готовым. Единственный источник правды — бэковая копия.
- `docs/frontend.md` — **твой файл**: конвенции кода, экраны,
  UI-решения. Правь свободно в этой копии; бэк-агент подтягивает
  её к себе сам.
- Свои рабочие файлы — только здесь: `optimizations.md`
  (журнал решений и план оптимизаций, включая открытые
  вопросы) и `bugs.md` (список багов в работе, создан
  2026-11-27; делаем по порядку, отмечаем сделанное).
  Старые планы и журналы (plan-*, fixes, status,
  menus, bugs-player, unthoughtout) удалены 2026-11-27:
  источник истины по текущему состоянию — код, `frontend.md`,
  `optimizations.md` и `bugs.md`.

## Как брать контракт

Типы из `contracts.md` копируются в `src/types/` — это единственный
источник правды о форме данных. Поле в ответе не сошлось с типом —
не подгоняй тип под ответ молча и не чини бэк сам: зафиксируй
расхождение (файл/поле/пример ответа) и передай пользователю —
контракт правит бэк-агент.

## Границы

В `~/projects/SkyFi` не лезем (ни кода, ни docs) — бэк-агент ведёт
там свои файлы. Встретил баг бэка / нужен новый эндпоинт / хочешь
изменение формы ответа — через пользователя, бэк-агент о таких
задачах узнаёт от него.
