# Релизы: когда APK, а когда достаточно OTA

Памятка. Дата: 2026-11-28. Скрипты лежат в `~/projects/SkyFi/scripts/`
(репо бэка), но работают с репо фронта (`~/projects/SkyFi_front`).

## Ментальная модель

Приложение состоит из двух частей с **независимыми версиями**:

- **Оболочка (натив, APK)** — «браузер»: Java-код в `android/`,
  манифест, пермишены, Capacitor-плагины, иконка и имя приложения.
  Версия — `versionName` в `android/app/build.gradle` (сейчас 1.1.x).
  Ставится системным установщиком Android. Меняется редко.
- **Бандл (веб)** — «сайт внутри браузера»: весь интерфейс и логика
  из `src/` (+ `index.html`, `public/`), собирается vite в `dist/`.
  Версия — `BUNDLE_VERSION` в `src/lib/bundle-version.ts`
  (сейчас 1.0.x). Прилетает по воздуху (OTA) и применяется без
  переустановки. Меняется постоянно.

Внутри каждого APK зашит бандл на момент сборки; поверх него OTA
ставит бандлы новее. Обе версии видны в настройках приложения:
«бандл X · APK Y».

**Правило одной строкой:** менял только веб-часть (`src/`) — OTA;
тронул `android/`, `capacitor.config.ts` или Capacitor-плагины — APK.

## Шпаргалка «что тронул → что запускать»

| Что изменилось | Релиз |
|---|---|
| Экраны, компоненты, стили, сторы, API-клиенты (`src/`) | OTA |
| `index.html`, `public/` (favicon и т.п.) | OTA |
| Обычные npm-пакеты без нативного кода (axios, hls.js…) | OTA |
| `docs/`, тесты, скрипты | ничего — в приложение не входят |
| `android/`: Java/Kotlin, `AndroidManifest.xml` (пермишены!), ресурсы, иконка/имя приложения | **APK** |
| `capacitor.config.ts` (настройки плагинов) | **APK** — конфиг зашивается в натив при `cap sync`, OTA его не меняет |
| Новый/обновлённый Capacitor-плагин (`@capacitor/*`, `@capgo/*`) | **APK** + см. «Комбо» ниже |
| Версия Capacitor | **APK** |

## OTA-релиз (частый случай)

```sh
cd ~/projects/SkyFi
./scripts/release-ota.sh patch "Что изменилось"
```

- **Перед:** закоммить все правки во фронте — с грязным деревом
  скрипт откажется работать.
- Версия: `patch` (1.0.32 → 1.0.33), `minor`, `major` или явная `X.Y.Z`.
- Скрипт сам: поднимет `BUNDLE_VERSION`, сделает коммит и тег `vX.Y.Z`,
  соберёт `dist/`, заархивирует и зарегистрирует на бэке.
- **После:** `git push && git push --tags` (скрипт не пушит).
- На устройстве: при следующей проверке (запуск, вход в настройки,
  pull-refresh) — диалог «Обновить до 1.0.33?» → скачивается ZIP →
  применяется без переустановки.
- `--mandatory` — диалог без «Позже».

## APK-релиз (редкий случай)

```sh
cd ~/projects/SkyFi
./scripts/release-apk.sh --shell=1.2.0 --notes="Что нового"
```

- Версию оболочки поднимать **всегда**: бэк сравнивает semver, а
  повтор той же версии отклоняет (409). `versionCode` скрипт
  увеличит сам — без этого Android не примет обновление.
- После скрипта **закоммить `android/app/build.gradle`** во фронте.
- Скрипт: бамп версии → сборка бандла из рабочего дерева (поэтому
  фронт тоже лучше закоммитить — в APK уедет то, что в дереве) →
  `cap sync` → gradle → публикация на бэке.
- На устройстве: диалог «Обновить приложение до 1.2.0?» → браузер
  качает APK → системный установщик → «Обновить». Данные приложения
  и скачанные OTA-бандлы сохраняются.
- Флаги: `--mandatory` (без «Позже»), `--no-publish` (только собрать
  локально), `--release` (release-подпись, нужен keystore).
- **Подпись:** обновление встаёт только поверх APK с той же подписью
  (debug-keystore этой машины). Сборка на другой машине = ручная
  переустановка с потерей данных.

## Комбо: бандлу нужна новая оболочка

Сценарий: добавил Capacitor-плагин и вызываешь его из `src/`.

1. `release-apk.sh --shell=1.2.0` — новая оболочка. APK уже несёт
   свежий бандл, так что отдельный OTA обычно не нужен.
2. Если бандл с вызовом плагина выпускаешь отдельным OTA (например,
   оболочка уже опубликована, а правки веба продолжаются) —
   **обязательно** с `--shell-min`:
   `./scripts/release-ota.sh patch "Под новую оболочку" --shell-min=1.2.0`.
   Бэк не предложит такой бандл старым оболочкам — вместо него
   устройство получит оффер APK.
3. Никогда не выпускай бандл, вызывающий новый нативный код, без
   `--shell-min` — на старой оболочке вызов упадёт.

## Как устройство выбирает

Приложение шлёт `GET /app-updates/check` с версиями бандла и
оболочки (`apk=1` — «умею ставить оболочку»). Бэк отвечает:
`kind: 'apk'` (есть оболочка новее — приоритет), `kind: 'bundle'`
(есть бандл новее и совместимый по `shell-min`) или `null`.
Контракт — `docs/api.md` §19, предложение — `docs/proposal-apk-updates.md`.
