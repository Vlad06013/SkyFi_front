# Контекстные меню — матрица и архитектура

Матрица «контекст → пункты меню» согласована с макетом (источник —
список заказчика, ноябрь 2026). Код: `src/lib/media-menu.ts`
(реестр и матрица), `src/components/EntityMenu/` (один компонент),
`src/composables/useMediaMenu.ts` (открытие и действия).

## Пункты-атомы (реестр)

Каждое меню — подмножество атомов. Подписи атомов, переключающиеся
по состоянию:

- `like` — «В избранное» / «Убрать из избранного» (по
  `useFavoritesStore.has`)
- `download` — «Скачать» / «Удалить скачанное» (по
  `useDownloadsStore.has`)

| Атом | Подпись | Особенности |
|---|---|---|
| `listen` | Слушать | коллекции (альбом/артист/плейлист) |
| `queue` | В очередь | треки и видео |
| `friend-queue` | В очередь другу | |
| `like` | В избранное / Убрать из избранного | переключатель |
| `playlist` | В плейлист | |
| `download` | Скачать / Удалить скачанное | переключатель; скачивание только треков |
| `share` | Поделиться | |
| `edit` | Изменить | свои плейлисты |
| `delete-playlist` | Удалить из плейлиста | danger; только внутри деталки плейлиста |
| `delete` | Удалить | danger; только источник skyfi |
| `lyrics` | Текст | плеер |
| `devices` | Устройства | плеер |

## Матрица контекстов

Ключ = место открытия. «т» = трек, «в» = видео, «к» = коллекция
(плейлист/альбом/артист).

| Контекст | Атомы |
|---|---|
| `my-tracks` (Моё·Треки·т) | queue · friend-queue · like · playlist · download · share |
| `my-playlists` (Моё·Плейлисты·к) | listen · like · download · share · edit · delete¹ |
| `my-playlist-track` (деталка плейлиста·т) | queue · friend-queue · like · download · share · delete-playlist |
| `my-playlist-video` (деталка плейлиста·в) | queue · friend-queue · like · share · delete-playlist |
| `my-albums` (Моё·Альбомы·к) | listen · like · download · share |
| `my-album-track` (деталка альбома·т) | queue · friend-queue · like · download · playlist · share |
| `my-artists` (Моё·Артисты·к) | listen · like · share |
| `my-videos` (Моё·Видео·в) | queue · friend-queue · like · playlist · share |
| `my-uploads` (Моё·Загрузки·т) | queue · friend-queue · like · download · playlist · share · edit³ · delete³ |
| `my-downloaded` (Моё·Скачано·т) | queue · friend-queue · like · download² · playlist · share |
| `friend-queue-track` (Друг·Очередь·т) | like · download · playlist · share |
| `friend-queue-video` (Друг·Очередь·в) | like · playlist · share |
| `friend-favorites-*` (Друг·Избранное) | табы как в Моём; меню = `my-*` по типу; like относится к СВОЕМУ аккаунту |
| `search-*` (Поиск, все табы) | = `my-*` по типу; like — переключатель у всех; видео переводим на общий `VideoRow` |
| `now-track` (Плеер·т) | queue · friend-queue · like · download · playlist · share · lyrics · devices |
| `now-video` (Плеер·в) | queue · friend-queue · like · playlist · share · lyrics · devices |

¹ `delete` только при `source_type === 'skyfi'`.
² в «Скачано» атом стартует в состоянии «Удалить скачанное».
³ edit/delete в «Загрузках»: edit открывает форму загрузки в режиме
  правки (префилл из трека), delete удаляет загрузку; оба пункта —
  только для своих загруженных треков.

## Архитектура: один компонент, декларативная конфигурация

Делаем ОДИН `EntityMenu`, но вместо веток `v-if` по вариантам он
принимает готовый список пунктов: `items: MenuItem[]`, где
`MenuItem = { id, label, icon, danger? }`. Никаких компонентов на
каждое меню — меню отличаются только набором атомов.

- **Реестр атомов** (`media-menu.ts`): id → иконка (svg) +
  функция подписи от состояния (like/download) + флаг danger.
- **Матрица контекстов** (`media-menu.ts`): ключ → массив id атомов,
  ровно таблица выше. Условные атомы (`delete` для skyfi) фильтруем
  при сборке.
- **Высота меню** считается из количества пунктов (строка 44px +
  отступы), таблица `menuHeight` удаляется — больше не рассинхронится
  с вёрсткой.
- **Открытие**: `openSnapshotMenu(event, snapshot, 'my-album-track')`
  вместо enum-вариантов. Состояние like/download подставляется
  компоузером при сборке items.
- **Действия** остаются в `useMediaMenu.run` (+ новые: снятие
  скачанного, delete для skyfi-плейлиста).

Почему не компонент на меню: 16 меню из 13 одинаковых атомов — было бы
16 копий одной разметки. Почему не текущие v-if-варианты: ветки уже
дублируют иконки, высоты захардкожены по местам и разъезжаются.

## Решения (согласовано)

1. «Удалить скачанное» — danger (красный).
2. Друг·Избранное (табы как в Моём) — отдельным заходом.
3. Плеер: like и «В очередь» в меню плеера — да, единая логика
   действий со снапшотами.
4. В «Загрузках» добавляем «Изменить» (открывает форму в режиме
   правки, префилл из трека) и «Удалить» (danger) — удаляет
   загруженный трек из мок-списка.
5. Подписи like/download собираются по состоянию
   (`favorites.has` / `downloads.has`) для всех контекстов единообразно:
   в «Треках»/«Скачано» переключатель фактически всегда в положении
   «Убрать…», но чек не зашит в контекст.
