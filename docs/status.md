# SkyFi Frontend — статус: что есть / чего нет

Живой трекер пробелов между контрактом (`api.md`, `contracts.md`,
`frontend.md`, `video.md`) и текущим кодом (`src/`). Все приложение
сейчас работает на моках: ни одного реального запроса к бэку,
ни сокетов, ни аудио/видео-движка.

Легенда: ✅ есть · 🟡 мок/частично · ❌ нет

## 1. Инфраструктурные слои

| Слой | Статус | Комментарий |
|---|---|---|
| `types/` (снапшоты, enum) | ✅ | Скопированы из contracts.md |
| `mocks/` (catalog, friends, player, user) | ✅ | Движут весь текущий UI |
| Роутер + гварды | 🟡 | Гвард смотрит на фейковый auth-стор, дефолт — залогинен |
| `api/` HTTP-клиент | ❌ | Нет совсем: ни axios-инстанса, ни обёртки `{errors,data,pagination}`, ни обработки 401/422/429 |
| Сокеты (Echo + Reverb) | ❌ | Зависимости в package.json есть, клиента нет; нет подписок, эхо-глушения, reconnect-рефетча |
| Регистрация устройства / heartbeat | ❌ | `origin_device_id` нигде не генерируется |
| Аудио-движок (`<audio>`, потоки, get-url, TTL-кеш) | ❌ | Позиция/прогресс не тикают, воспроизведения нет |
| Видео-движок (`<video>`, streams, качества) | ❌ | Только фон-картинка в клип-режиме |
| Локальное хранилище (Dexie/Preferences) | ❌ | Токен, кеш избранного, история поиска, очередь мутаций — ничего не персистится |
| MediaSession (кнопки руля, BT, экран блокировки) | ❌ | Зависимость @capgo/capacitor-media-session есть |
| Фоновое воспроизведение / аудиофокус | ❌ | |
| Офлайн-детект (`GET /health` + сокет) | ❌ | |
| Тесты (vitest настроен, `tests/` пустая) | ❌ | |
| Конвенция «папка = X.vue + X.ts + X.css» | 🟡 | Сейчас единые `.vue` со встроенным `<script setup>`; styles/ кит перенесён |

| Поиск | 🟡 | Строка, история (хардкод), пилюли 6 секций, мок «Лучшего»/треков/видео | Запросы `GET /search` (пагинация, has_more, best), вставка ссылки, is_favorite, пагинация «показать ещё», офлайн-поиск по локальному, история в БД |
| Детали: альбом | 🟡 | Hero, список (все треки из мока избранного) | Состав по API, кнопка «играть контекстом» как контекст плеера, лайк |
| Детали: артист | 🟡 | Hero, список треков | Фильтр «треки/альбомы» (есть в макете), данные по API, лайк |
| Детали: плейлист | 🟡 | Hero, список, лайк, флаг «свой» | Создание (кнопка-заглушка в «Моём»), add/remove/reorder, обложка, видимость, «играть контекстом», внешний плейлист read-only |
| Медиатека («Моё») | 🟡 | 6 вкладок, drag&drop сортировка треков (локально), строка «скачать всё» (мок-статусы) | Данные из API, сорт синкается (`/favorites/sort`), вкладки «Загрузки» и «Скачано» — заглушки, лайки реальные |
| Друзья | 🟡 | Список моков, 1 входящая заявка (принять/отклонить локально), поиск по мокам | Заявки/дружба по API, исходящие, поиск пользователей + статус заявки, now-playing из сокетов |

| Устройства | 🟡 | Есть шит выбора активного устройства (мок-список) | Отдельный экран по макету: presence, активация (`PATCH /devices/{id}/activate`), удаление |

| Авторизация | 🟡 | Все 5 режимов UI: login/register/forgot/reset/qr | Всё фейковое: нет запросов, нет токена/сессии, QR — заглушка (нет store/show/confirm/поллинга), валидация 422, сброс по коду из письма |
| QR с телефона (подтверждение чужого входа) | ❌ | Макет `design/phone/qr.html` есть | Экран сканирования/подтверждения `POST /qr-login/confirm` |

## 3. Плеер (ядро, §5 frontend.md)

| Возможность | Статус | Комментарий |
|---|---|---|
| Сервер как источник истины (`GET /player`, version) | ❌ | Стор — локальная копия мока |
| Команды play/pause/seek/options с эхо-полями | ❌ | Все действия локальные |
| Контекст воспроизведения (play_source, курсор) | 🟡 | `playSnapshot` ставит `single`; контекстов favorites/playlist/wave нет |
| Виртуальный поток (история + текущий + очередь + остаток) | 🟡 | Очередь есть (мок), истории и точки возврата нет |
| Схема next/prev (очередь → контекст → repeat → избранное) | 🟡 | Упрощённо: next = первая в очереди, иначе цикл по избранному; prev с рестартом <3с есть |
| Shuffle (перемешанная копия, курсор вокруг текущего) | ❌ | Только флажок |
| Кросс-девайс (пульт, activate, presence) | ❌ | `activateDevice` только переключает флажок в моке |
| Применение состояния (команда → сокет → reconnect) | ❌ | |
| Очередь: add/remove/reorder по API, статусы pending/played | 🟡 | Локальный массив треков; `QueueItem`-модель со статусами не используется |
| Now-playing: обложка/лирика/очередь/свайпы | 🟡 | UI готов (слои now/queue/lyrics), лирика захардкожена, нет `/audio/lyrics` |
| Мини-плеер | 🟡 | Есть, но прогресс захардкожен 38% |

## 7. Предлагаемый порядок работ

1. **Фундамент**: `api/`-клиент (обёртка, ошибки, троттлинг-тосты), токен/сессия, регистрация устройства, Echo-клиент с эхо-глушением.
2. **Авторизация по API** + QR-флоу (обе стороны).
3. **Плеер-ядро**: аудио-движок, контексты и схема воспроизведения, серверная очередь, кросс-девайс, MediaSession.
4. **Поиск + детали сущностей**.
5. **Медиатека**: избранное (лайки/сорт), плейлисты CRUD, загрузки.
6. **Друзья + шары + уведомления**.
7. **Видео-режим**.
8. **Офлайн + скачивание + предзагрузка**.
9. **TV/car**: D-pad-фокус, QR-вход, профили адаптива.
10. Параллельно: приведение файлов к конвенции §2.1, тесты, недостающие макеты.

Правило обновления: правим код → правим этот файл. Сначала `api.md`,
потом `contracts.md`, потом код, потом статус здесь.
