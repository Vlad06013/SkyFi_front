### Позиция: модель переписана по решению «локальный плеер — главный»

`src/stores/player.ts`:

- **Целые секунды + тикание раз в секунду.** Убрана вся математика
  миллисекунд от `position_updated_at` (потолок доверия 30 с, докид
  `now − штамп`). Якорь — целые секунды, экстраполяция —
  `anchor + floor((now − anchorAt)/1000)` с клампом снизу 0 (между
  применением якоря и ближайшим тиком тикера floor давал −1 — позиция
  на секунду прыгала назад). Поле `position_updated_at` нигде не
  читается и не пишется (в стейте остаётся только потому, что его шлёт
  контракт).
- **Играющее устройство — источник правды своего звука.** Позиция идёт
  из аудио-элемента (timeupdate → якорь, округлённый до секунды).
  Серверную позицию принимаем только когда сокет-ивент несёт ЧУЖУЮ
  позицию (`lastPositionPushSeconds` — последнее, что сами отправили:
  репорт/seek/пауза/play; совпала ±1.5 с → слияние по владению, не
  совпала → применяем целиком = перемотал другой девайс) или сменился
  трек/is_playing. Штамповый гейт «свежее >1 с → целиком» удалён —
  бэк штампует свежим временем в каждом housekeeping-broadcast'е,
  по штампу ивент не отличить от чужого seek'а — это и было
  «буксование».
- **Пауза бросала на 0 — закрыто.** Причина: сырое `state.position_seconds`
  (последний seek/репорт, часто 0) устаревало, а якорь на паузе брался
  из него. Теперь перед любым стоп/паузой/офлайн-тоглом локальная
  позиция пишется в стейт (`writeLocalPosition()`), откаты тоже
  сохраняют позицию.
- **Слияние по владению больше не дёргает прогресс:** якорь при
  `applyServerStateMerged` не пересаживается (элемент свежее любого
  замера; раньше раз в 10 с прогресс подпрыгивал).
- **Локальный seek (<2.5 с) доезжает до элемента:** `seek()` округляет
  до секунды и бампает `mediaSeek` (вотчер подгонки глушил мелкие
  seeks: порог 2.5 с без форс-флага).
- `lastPositionPushSeconds` фиксируется при каждой отправке позиции
  (репорт/seek/пауза/play/рестарт) и ОТКАТЫВАЕТСЯ при сетевой ошибке —
  иначе следующий housekeeping-ивент снялся бы как «чужой seek».
- Инструментация: `[player] socket merged/force позиция=… push=…`,
  `[player] report: шлём N с`, `[audio] подгонка: стор/элемент/ключ`.
- Тесты переписаны под секундную модель + регрессионные: «пауза не
  сбрасывает в 0», «тикание +1/с», «чужой seek из сокета применяется»,
  «свой housekeeping-ивент не дёргает позицию» (tests/unit/stores/
  player.spec.ts, 70 тестов).
- `docs/frontend.md` §5 переписан под новую модель (штампы/окно
  доверия убраны, добавлен абзац «Позиция — секундная модель»).

### Скачивание: нативный путь на axios с прогрессом

- Корень 422 найден ранее: `Filesystem.downloadFile` тело POST вообще
  не пишет (поля `data` нет в нативном коде плагина) — stringify не
  помогал бы никогда.
- Теперь `storeFile` (src/stores/downloads.ts) качает через
  `fetchAudioFile` (axios) на ОБЕИХ платформах: бэк отдаёт
  Content-Length → `onDownloadProgress` → спиннер заполняется. Нативный
  CapacitorHttp-вариант удалён (он не шлёт байтовый прогресс — спиннер
  стоял пустым). Убраны `downloadTrackFile` (src/lib/download-files.ts)
  и `audioFileUrl` (src/api/audio.ts).
- Ограничение: файл целиком в памяти (десятки МБ), таймаут axios 180 с.
- Откат глушения зонда доведён до конца: downloads.ts ещё звал
  `online.suspendProbes()/resumeProbes()`, которых в сторе уже не было, —
  сборка (vue-tsc) была сломана. Вызовы удалены.

### Диагностика офлайн-флапа (наблюдение, логика детекта НЕ менялась)

- `src/api/health.ts`: `probeHealth()` возвращает `{ ok, durationMs,
  miss, detail }`; тип промаха: timeout (ECONNABORTED) / network
  (ERR_NETWORK — сброс соединения, «Software connection abort») /
  http (статус) / payload (200 без status=ok) / unknown. `checkHealth`
  — обёртка над ним, контракт прежний.
- **Фикс классификатора:** http-интерцептор конвертирует axios-ошибки
  в ApiError, и код терялся — все промахи были «сбой». Теперь ApiError
  несёт `code` (src/api/http.ts), classify читает его.
- `src/lib/health-log.ts`: кольцевой журнал (100 записей) в памяти +
  Preferences (`skyfi.health-log`, переживает перезапуск APK). Запись:
  время, длительность, тип промаха, деталь, активность, переход
  онлайн/офлайн. `formatHealthLog` — текст для копирования.
- Активность в момент зонда: пробы регистрируют плеер (`играет`,
  `play без звука`, `грузит поток`, `буфер`, `seek`) и скачивания
  (`скачивание всё N/M`, `файл N%`).
- Экран: «Настройки → Диагностика сети» — журнал новыми сверху, кнопки
  «Копировать» (в буфер, текстом) и «Очистить». На телефоне консоль
  WebView недоступна — это единственный канал наблюдения.
- Моки `@/api/health` в спеках (app/guard/Login) деривируют
  `probeHealth` из мока `checkHealth`.

### Разбор журналов с устройства (2026-11-26 вечер)

- **LTE + «скачать всё»:** health 0.2 с → 9.7–14.4 с (в 0.6 с от
  таймаута 15 с). Переходов в офлайн не было.
- **Wi-Fi + «скачать всё»:** health 0.1–1.0 с на том же объёме —
  **сервер невиновен**: PHP-FPM/nginx health тянут и под закачкой.
  Деградация на LTE — это радиолинк телефона (bufferbloat), не бэк.
  Вопрос бэку про воркеры НЕ нужен.
- **Выключение Wi-Fi:** один промах 15.0 с (таймаут) → восстановление
  через 5–10 с по LTE, endpoint перерезолвился («повтор после смены
  адреса»). Гистерезис двух промахов отработал, флапа не было.
- **Пойман сталл стрима:** файл встал на 66% на 40+ с при health 0.1 с —
  тело /audio/file перестало течь (прокси бэка). Закрыто сталл-детектором.
- **Самоостановка трека (LTE-окно):** `is_playing` стал false без тапа —
  подозрение на серверный бродкаст при протухании presence (heartbeat не
  доезжал в перегруженное окно). Вопрос бэку открыт (см. ниже).

### Фиксы по журналам и репортам (2026-11-26 ночь)

- **Сталл-детектор скачивания** (`fetchAudioFile`): нет байтов 30 с
  (`AUDIO_STALL_TIMEOUT_MS`) → обрыв + одна повторная попытка; отмена
  пользователем — мимо ретрая. Тесты tests/unit/api/audio.spec.ts.
- **Проклик мини-бара закрыт корнем:** click жеста диспатчится после
  pointerup по координатам и лендил в свежеоткрытый NowPlaying (кнопка
  «нажималась», раньше — тоглилась). `openExpanded` теперь макротаском
  (setTimeout 0) — click достаётся мини-бару. Костыль с глушением
  click'ов 400 мс (`onShellClickCapture`, `openedAt`) удалён целиком.
- **Превью клипа на главной залипало:** keep-alive возвращает вкладку
  без смены ref'ов — вотчер хостов молчал, видео оставалось в парковке.
  Добавлены `resyncClipAttachment()` (onActivated главной) и отложенный
  синк после установки хоста (раскладка ещё не посчитана — getClientRects
  пуст, немедленный синк парковал элемент).
- **Пустой `<video>`** (серая заглушка с чёрным треугольником WebView)
  скрыт до первого кадра: `.clip-video { opacity: 0 }` до `is-ready`.
- **UX «скачать всё»:** процент кнопки — max(доля задания, общая доля
  скачанного) — повторный прогон не сбрасывает 7%→1%; левая подпись
  плашки — «N/M · текущий трек» (bulk.current); у строки трека до
  первых байтов крутится индикатор (раньше — пустое кольцо).
