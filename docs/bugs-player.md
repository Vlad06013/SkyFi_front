# Плеер/сеть — живые баги и контекст (2026-11-26, вечер)

Файл для продолжения после перезапуска контекста. Симптомы — с реального
телефона (RMX3370, Android 13, LTE). Время nginx-логов UTC, местное = UTC+7.

## Статус: оба корня найдены, фиксы в коде (452 теста зелёные, сборка ок)

### 1. «Буксование» позиции — КОРЕНЬ НАЙДЕН и закрыт в коде

Роутер сокетов глушит своё эхо (origin_device_id), сторонних устройств в
момент теста не было — дёргались housekeeping-broadcast'ы сервера
(регистрация устройства, presence-планировщик): сервер шлёт
`playback.state.updated` со СВЕЖИМ `position_updated_at`, а позиция в нём —
последний репорт (до 10 с отстаёт от реального звука).

Старый гейт в `applySocketState` решал «merged vs целиком» по штампу:
`theirsStamp > mineStamp + 1000` → применить стейт ЦЕЛИКОМ. У housekeeping-
ивента штамп всегда свежее локального → force-подмена → экстраполяция
схлопывалась в округлённый репорт → вотчер подгонки (`|el − serverPos| > 2.5`)
отматывал элемент назад → timeupdate возвращал якорь → следующий broadcast
снова назад. Цикл «назад-вперёд» = буксование прогресс-бара и звука.

Фикс (src/stores/player.ts): вместо сравнения штампов — сравнение позиции
ивента с `lastPositionPushSeconds` (позиция, которую мы сами последней
отправили: репорт раз в 10 с, seek, пауза, /play, рестарт).
Транспорт совпал + позиция наша (±1.5 с) → слияние по владению, звук не
трогаем. Позиция чужая (пульт seek'нул) или транспорт другой → целиком.
После полной подмены `lastPositionPushSeconds` встаёт на серверную позицию,
чтобы следующие broadcast'и с той же позицией не дёргали зеркало.

Регрессионные тесты: `tests/unit/stores/player.spec.ts`, describe
«позиционный репорт» — «housekeeping-ивент… (merged)» красный на коде до
фикса (проверено stash'ем), зелёный с ним; «чужая позиция… (seek с пульта)»
— страж обратной стороны.

Инструментация для проверки на устройстве (chrome://inspect → WebView):
- `player.ts applySocketState`: `[player] socket merged/force позиция=…
  push=… версия=…` на каждый сокет-ивент;
- `player.ts reportPosition`: `[player] report: шлём N с`;
- `useAudioPlayback.ts` вотчер подгонки: `[audio] подгонка: стор X,
  элемент Y, ключ …`.

Ожидаемое поведение на устройстве: при буксовании в логе видно, ушли ли
ивенты в `merged`. Если звук всё же дёрнется — лог покажет, какая ветка
сработала и с какими числами.

### 2. Скачивание 422 — КОРЕНЬ НАЙДЕН и закрыт в коде

`Filesystem.downloadFile` (нативный код плагина, LegacyFilesystemImplementation)
**вообще не пишет тело запроса**: там читаются url/headers/params/method/
path, поля `data` нет. POST /audio/file уходил с пустым телом → Laravel
422 «type field required». stringify-фикс не мог помочь — плагин тело
выбрасывает независимо от формы. Подтверждено чтением исходников плагина
(@capacitor/filesystem 8.1.5) — фиксировать расхождение плагина с нашими
ожиданиями не к кому, это его документированное ограничение.

Фикс (src/lib/download-files.ts): нативный путь переписан на
`CapacitorHttp.request` (плагин встроен в @capacitor/core, нативная часть
уже внутри APK — релизится OTA без новой оболочки; JSON-тело пишется через
setRequestBody, запрос идёт нативно вне пула WebView). Ответ с arraybuffer
приходит base64 → Filesystem.writeFile в `.part` → rename. Не-2xx ответы
теперь вскрываются: тело (Laravel кладёт туда errors валидации) декодируется
и попадает в текст ошибки → тост покажет причину, если что-то снова
пойдёт не так.

Регресс по UX: CapacitorHttp не шлёт прогресс по байтам — на нативе
индикатор скачивания работает без процента, отчёт одним финальным кругом
(размер файла возвращается из downloadTrackFile, в storeFile кладётся
в запись). Веб-путь без изменений.

## Что проверить на устройстве (после OTA-релиза)

1. Скачивание трека: должно пройти без «error downloading». Если вдруг
   упадёт — тост покажет текст 422 (каких полей не хватает) — сразу сюда.
2. Проигрывание трека за пределы ~10–15 с: буксования быть не должно;
   в логе WebView ивенты `[player] socket merged (своя позиция)`.
3. Seek с ползунка на другом экране/пульте (если есть чем): позиция
   применяется (`socket force (чужая позиция)`).
