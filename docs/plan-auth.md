# SkyFi — план: интеграция API, этап «Авторизация»

Живой план поэтапной интеграции авторизации с реальным бэком.
Источники правды: `api.md` (§1, §3, §18), `contracts.md`,
`frontend.md` (§2.2 слои, §4 карта, §11 хранилище). Идём по
шагам: шаг не закрыт — следующий не начинаем. Правило дрейфа
те же: сначала `api.md`/`contracts.md`, потом код, потом этот
план и `status.md`.

## Принципы этапа

- Моки авторизации выключаются полностью: без токена —
  только экран входа. Никаких флагов-заглушек.
- Временных затычек нет: сразу полный функционал по
  контракту (вход, регистрация, сброс, профиль, QR обеих
  сторон).
- Каждый шаг закрывается тестами (см. «Тестовая стратегия»)
  и проходит `npm run build` + `npm run lint` + `vitest run`.
- Слои по frontend.md §2.2: `api/` не знает про stores,
  stores не знают про компоненты. Связь http↔стор —
  через колбэк-инъекцию из `main.ts`.

## Проверено на живом бэке (curl, 192.168.8.33:8080)

- `GET /api/v1/skyfy/health` → 200, обёртка ровно по §1.1:
  `{"errors":null,"data":{"status":"ok","server_time":…},
  "pagination":null}`. Голый `/health` → 404 (Laravel).
  Вывод: health стучим по `{baseURL}/health`.
- `POST /register` с `{}` → 422, `errors` — объект
  «поле → [сообщения]», как в §1.1. Маппинг `ApiError.fields`
  фиксируем по этой форме.
- Dev-база пустая: аккаунт заводим регистрацией через UI,
  тестовый аккаунт не нужен. Для проверок curl'ом заведён
  `test@skyfi.app` / `password123` (id 1) — можно входить.
- `POST /register` → `data: {token, user: {id, name, email,
  avatar_url}}`; `GET /user` с Bearer → та же форма user.
  Дрейф пойман: поле `avatar_url`, а не `avatar` (правка
  внесена в contracts.md).
- **QR-вход прогнан целиком curl'ом** (блокер снят):
  `POST /qr-login` → `{code, expires_at, qr_svg}` (без auth);
  поллинг `GET /qr-login/{code}`: `pending` c `token/user:
  null` → после confirm `{status: "confirmed", token, user}`;
  `POST /qr-login/confirm` (auth) `{code}` → 200; нет кода —
  404 «QR-код не найден.», без токена — 401. Бэк отдаёт
  готовый QR в SVG — своя генерация (библиотека `qrcode`)
  не нужна, рендерим `qr_svg` как есть.
- Письмо сброса: куда падает не важно, код вводится руками.

## Зафиксированные решения

- Токен — `@capacitor/preferences` (как планирует
  frontend.md §11; на вебе плагин сам работает поверх
  localStorage, для APK после правок — `npx cap sync`).
  Обёртка — `src/lib/session.ts`.
- QR рисуем локально: библиотека `qrcode` → dataURL в `<img>`.
  В QR кодируем ссылку `<origin>/qr-confirm?code=…`, телефон
  открывает её камерой → экран подтверждения в приложении.
  Отдельный in-app сканер камеры не делаем.
- **Офлайн-детект — часть фундамента, не откладываем.**
  `GET {baseURL}/health`, таймаут 5 с, период 10 с, крутится
  весь жизненный цикл приложения на любой странице. Стор
  `stores/online.ts`, интервал живёт в сторе (направление
  stores → api разрешено). На нативе поллер паузится в фоне
  через `@capacitor/app` (appStateChange) и дёргается сразу
  при возврате. Тостов/шума от провалов health нет — это
  зонд, а не пользовательское действие.
- **Сплэш до роутера, два слоя**: статичный в `index.html`
  (чёрный фон, SVG-логотип, надпись «SkyFi» — виден до
  загрузки JS, на девайсе с первой миллисекунды) и компонент
  `src/components/AppSplash/` по §2.1, который висит, пока
  идёт bootstrap. Макета нет — стиль тупо чёрный фон, знак и
  словесный логотип по центру (знак — из локапа Login).
- **Порядок старта (bootstrap)**: mount приложения сразу →
  сплэш → первый health (до 5 с) → дальше по матрице:
  - онлайн + токен → `restoreSession` (GET /user) → `/home`;
  - онлайн + нет токена → `/login`;
  - офлайн + токен → в приложение (сессия была, офлайн
    допустим по frontend.md §8; серверный функционал дальше
    честно падает в офлайн-состояния);
  - офлайн + нет токена → `/login` с баннером «Нет
    соединения»: сабмит форм заблокирован (клиентская
    проверка `online.isOnline` + тост), кнопка «Повторить»
    запускает bootstrap заново.
- **Гвард не решает до готовности**: `main.ts` запускает
  `bootstrap()` и кладёт promise в модуль; `beforeEach`
  делает `await` того же promise. Один запуск, никакого
  флика `/ → /login → /home`.

## Тестовая стратегия

Инструменты уже в проекте: vitest + jsdom, @vue/test-utils,
cypress. `tests/unit/setup.ts` подключён в vite.config, но
файла нет — создание входит в шаг 0. Новых библиотек-моков
не вводим: axios и модули api мокаем через `vi.mock`,
таймеры — `vi.useFakeTimers`, pinia — `setActivePinia`.

Слои тестирования (отвечают на вопрос «что тестируем»):

1. **Клиент (`api/http.ts`)** — поведение против формата
   ответа бэка (api.md §1.1, §1.2, §18; форма 422 проверена
   curl'ом):
   - успех: распаковка `data` из обёртки, отдача наружу;
   - заголовок `Authorization: Bearer` подставляется из
     сессии;
   - маппинг ошибок в типизированный `ApiError`: 401,
     404/403 (сообщение из `errors`), 422 (объект полей,
     ключи → массивы строк), 429, 502/503, сетевой сбой
     (`code === 'ERR_NETWORK'`);
   - вызов зарегистрированного `onUnauthorized`-колбека
     ровно один раз на 401.
2. **Методы API (`api/auth.ts`, `api/qr.ts`, `api/health.ts`)**
   — контрактные тесты: мокаем http-клиент, проверяем
   метод/URL/тело/версию пути (§3 api.md) и тип возврата.
   У health отдельно: таймаут 5 с, любой не-200/сбой = offline.
3. **Хранилище сессии (`lib/session.ts`)** — с моком
   плагина: set/get/clear, поведение при отсутствии ключа.
4. **Стор (`stores/auth.ts`)** — сценарии:
   - login/register: успех → user+token в состоянии;
     ошибка → состояние чистое, ошибка проброшена форме;
   - restoreSession: валидный токен → `GET /user`, isAuthed;
     401/сеть → гость, токен стёрт;
   - logout: `POST /logout` (best-effort, ошибка не валит),
     состояние и хранилище чистые;
   - 401-хук: сброс состояния + редирект на `/login`
     (мок роутера).
5. **Онлайн + bootstrap (`stores/online.ts`, `stores/app.ts`)**
   — с fake-таймерами и мок-api:
   - поллер: первая проверка сразу, следующая через 10 с;
     успех → isOnline, таймаут/сбой/не-200 → offline;
     восстановление после провала;
   - bootstrap-матрица: онлайн×токен (4 кейса из раздела
     решений), bootstrap выполняется один раз при повторных
     await;
   - splash держится, пока `phase !== 'ready'`.
6. **Гвард роутера** — интеграционно: ждёт bootstrap-promise;
   `requiresAuth` без сессии → `/login?redirect=…`;
   `guestOnly` с сессией → `/home`; офлайн без токена →
   `/login` с баннером.
7. **Страницы (Login, QrConfirm, Settings-профиль)** —
   @vue/test-utils, мок-стор/мок-api:
   - сабмит форм вызывает действие стора с полями формы;
   - 422 → `.field.is-error` + текст ошибки на нужном поле;
   - loading на кнопке на время запроса;
   - редирект на `redirect`-query после входа;
   - офлайн: сабмит заблокирован, баннер «Нет соединения»,
     «Повторить» перезапускает bootstrap;
   - QR-режим: поллинг по таймеру, confirmed → вход,
     expired → кнопка «Обновить QR» (таймеры — fake);
   - смена режимов login/register/forgot/reset.
8. **e2e (cypress, последним слоем)** — против живого бэка:
   регистрация → вход → выход → редирект на /login;
   «просроченный токен → 401 → на вход»; сплэш → home;
   сплэш → login при отсутствии токена; forgot → письмо →
   reset (код руками — сценарий прогоняем вручную, e2e
   опционально); QR-флоу: второй клиент — через
   `cy.request` на confirm.

Юниты пишутся в том же шаге, что и код. e2e — после шага 4.

## Итоги и дрейф плана (зафиксировано по факту)

- **CORS**: dev-proxy из шага 0.2 не понадобился — бэк отдаёт
  `Access-Control-Allow-Origin: *` и эхо разрешённых заголовков
  (проверено preflight с `Authorization`). `.env` с абсолютным
  URL работает и в dev, и для APK.
- **Сессия** хранится как `{token, user}` одним JSON (`skyfi.session`)
  — офлайн-вход по сохранённому профилю без `GET /user`.
- **Роутер** стал фабрикой `createAppRouter()` — гвард вшит в
  фабрику, юнит-тесты живут со своим роутером на тест.
- **401**: интерсептор глушит сброс сессии, если в запросе не было
  Authorization (неверный пароль при входе не рвёт сессию).
- **QR**: бэк отдаёт готовый `qr_svg` — своя генерация не нужна;
  кнопка «Войти по QR» в офлайне не disabled, а отвечает тостом.
- **e2e-флак**: dev-троттлинг 6/мин на login/register — между
  прогонами `cypress run` пауза ~минута.
